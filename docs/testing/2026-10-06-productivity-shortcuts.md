# gototerm 操作改善の検証記録（2026-10-06）

実装ブランチ: `feat/productivity-shortcuts`。既存の利用者編集はコミットから除外。

## 実装範囲

- Windowsを含むURL判定: HTTP/HTTPS、OSC 8、日本語・全角セル、端末の自動折り返し、スクロールバック。マウス報告TUIでもCtrlクリックで開く。
- Ctrl+1〜9 / Ctrl+0によるタブ移動。作業フォルダ名と選択アクセントの一行タブ表示。
- Ctrl+Shift+Spaceのコピー専用モードとVim風の移動・文字/行/矩形選択。
- Ctrl+Shift+Rのリンクヒント。画面更新時の候補取消、接頭辞が衝突しないラベル、本文を変更しない描画。
- ランチャーのwから名前付き作業セットを保存・選択・削除。タブ/分割/cwdだけをローカルJSONに保存。
- Windowsのペインごとの名前付きパイプとClaude Code/Codex helper。明示的なフック設定追加/解除、既存設定の保持。

## 検証結果

- `cargo test --quiet`: 309成功、1除外、失敗なし（除外は既存の性能測定）。
- `cargo build --quiet`: 成功。
- `cargo clippy --all-targets --quiet`: 終了コード0、警告あり、エラーなし。
- 変更したRustソースの`rustfmt --check`: 成功。全体の`cargo fmt --check`は既存の未変更ファイルに差分があり失敗。無関係な整形は行っていない。
- Helper CLIの結合検証: ユーザーフック/TOML保持、初回バックアップ、再実行、解除、不正JSON時の書き込み前検査、入力上限、判断を含まない標準出力が成功。
- Windowsパイプモジュール: ホスト上のRustメタデータ型検査が成功。Windowsでの実行確認を意味しない。

## レビューと修正

独立レビューで指摘されたImportant 2件を修正し、各回帰テストで失敗から成功を確認した。

1. 履歴上限に到達して未選択の状態でも、出力追加でコピーカーソルが別の行へ飛ばない。履歴サイズの増加に頼らず、内部の一時選択で回転量を追跡する。一時選択は描画前に除去する。
2. 観測できないcwdを親gototermのcwdで代用して保存しない。取得できないペインの保存を拒否し、相対ファイルヒントも出さない。WindowsではOSC 7導入を案内する。

## 実装上の判断

- 既存の未コミット編集を保つため専用ブランチで作業。別の作業ディレクトリは作らず、物理的な分離は弱い。
- 独立したコピー状態クラスではなくalacrittyのViカーソル/選択を再利用。出力追跡の補正を加える。依存するコアの動作変更時は回帰テストで確認する。
- タブの下線は追加せず、既存セルのアクセントと背景色を使用。見た目は文字による設計例と完全には一致しない。
- 作業セットは新しいタブへ追加し、既存プロセスを保持。ローカルの観測済みcwdだけ保存。復元時は追加のタブになり、リモート接続を再現しない。
- Windows IPCは限定したKernel32 FFI宣言を使用して依存を増やさない。Windows ABIと実動作の確認が残る。
- Codexの既存TOMLは変更せずhooks.jsonへ追加。仕様上の併用に従うが、Codexが併用警告を出す場合がある。
