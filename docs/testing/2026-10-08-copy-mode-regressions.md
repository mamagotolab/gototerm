# v0.6.19 コピー入力・境界の回帰確認

## 確認した不具合と修正

- 末尾への要求待ち中に逆方向を入力すると、新要求が古い要求と相殺・破棄された。未送信の旧方向要求を取り消し、境界処理でも逆方向要求を保持する。
- コピー専用中のマウス押下でTUI保持を解除した後、`copy_keyboard=true`だけが残った。Esc/Yの通常分岐がこのフラグを解除せず、入力を捕捉し続けた。共通終了処理へ統一し、VTモードの有無にかかわらず解除する。
- IME確定入力は通常入力と違ってマウスコピーの保持を解除しなかった。確定入力前に選択・保持画面を解除し、最新表示へ戻す。

## ローカル検証

- 全体330成功、5ignored、失敗0。逆方向とEsc解除の回帰は旧処理で失敗を確認してから修正。
- 明示実行した実PTY4件成功: lessの末尾からの逆方向移動、mutt標準pager、Vimのコピー、Vimの日本語本文に対する `:%s/* /  /g` の表示と保存内容。
- Xvfbの仮想GUIに実キー・マウス入力: v0.6.18はコピー中クリック→Esc→Vim置換・保存が失敗。修正後releaseビルドでは同一手順成功、保存ファイルが期待するUTF-8本文と一致。
- 独立レビューで残る重大な問題なし。個人のメール・会話・SSH接続先は検証に使用していない。

## Windows検証と限界

- CIに公式Windows版Vimの固定配布物・SHA256確認を追加。実ConPTYでコピー中のスクロールと日本語本文の置換・保存を確認する。
- 修正前の検証でもWindows版Vimの置換・保存とコピー内容の確認は通過した。終了後のファイル削除だけがプロセス終了待ち不足で失敗し、終了待ちを追加した。
- Windows→SSH先のVimでの本文表示崩れは未再現。今回の解除・IME修正と同一原因とは断定していない。Windows GUIの実操作も未確認。
- Linux debugビルドのX11起動はx11-dl内のnull referenceで停止した。GUI回帰の確認には配布と同じreleaseビルドを用いた。
- CI・配布の最終結果はGitHubのv0.6.19と対応PRを参照。
