# 全画面アプリの連続コピー検証（2026-10-07）

実装: `fix/tui-copy-scroll`。ユーザー承認済み設計と実装計画に基づき、既存のユーザー編集と分離したworktreeで実施。

## 結果

- ローカル`cargo test --quiet`: 327成功、4除外、失敗なし。除外は既存の性能測定1件と実アプリを必要とするPTY検証3件。
- 除外した実アプリ検証は別途実行し、less・mutt 2.4.2・Vim 9.2.1164の3件が成功。架空の80行本文とローカルmboxを使用。個人のメール・会話やユーザー設定は使用しない。
- less: 15行先へ進み、3行戻っても選択の始点を保持し、期待する本文を欠落・重複なく取得。
- Vim: rulerを有効にし、カーソルが中央の状態から下へ進める。本文が動かないカーソル移動を bounded retry で続け、複数画面の本文を取得。
- mutt: 標準pagerのnext-lineはEnter、previous-lineはBackspace。下矢印は別メールへの移動なので使用しない。専用入力で12回の行送りと選択保持を確認。
- Claude Code / Codex: モデルへの入力を送らない起動プローブで端末モードを確認。この環境のClaude Codeは通常画面・マウス報告なし、Codexは代替画面・SGRマウス報告・同期描画を有効にする。Claude Codeは既存の端末履歴コピー、Codexはライブスクロールの経路を使用する。
- 変更Rustファイルのrustfmtと`git diff --check`は成功。

## 独立レビューと回帰修正

- 部分描画を最長の一致から連結する問題: 本文の境界推定をやめ、選択とは別に最低3行の照合文脈を保持して領域全体を比較。新しい露出行が残存行と同一の曖昧な更新も停止する。失敗から成功への回帰テストを確認。
- 空の押下直後には通常マウス選択を取得できない問題: 非空の選択を初回ホイールで取得。押下→ドラッグ→スクロールのテストを追加。
- 1〜2行選択から継続できない問題: 選択と照合文脈を分離。1行選択の継続を検証。
- 逆ドラッグの始点と解放後の方向: 物理的な押下・解放位置を保持。ポインタが後から移動しても方向を変えない。
- Vimのカーソルだけの移動とruler更新: 本文不変をフッター更新と区別し、無マウスの入力を画面行数まで再試行する。
- レビュアーが最後の修正も確認し、指摘の残件なし。

## 判断と限界

- 最初の選択の範囲と前後の最低3行を照合文脈として固定。固定領域以外の全文を取得せず、本文の移動を推測で補わない。
- Windows/SSH/WSLなど前景muttを識別できない場合は、コピー専用モード中Mでmutt用を明示する。未知のアプリへEnterを推測で送らない。muttの独自キー設定は標準profileの検証範囲外。
- 実アプリの描画完了を一般的に通知する仕組みはないため、スクロールを直列化し描画の静止を待つ。反復行・検索ジャンプ・途中更新など判定不能時は保持済みの選択を残して停止する。任意のTUI描画について正確な全文取得を保証するものではない。
- 一時コピー履歴はメモリのみで既存履歴行数が上限。上限前に継続を停止する。
- GUI接続がないため、マウスの実操作、クリップボード実機、Claude Code/Codexの会話画面での選択は未確認。起動時の端末モード確認は会話の長文コピーの実機検証を意味しない。
- Windows/Linux CIと配布用ビルドはGitHubで確認し、リリース結果はv0.6.18の公開ページを参照する。
