# gototerm Windows 端末品質改善 設計

## 目的

Windows 版 gototerm で確認されている描画品質、タブ間のワークベンチ状態共有、メモリ使用量、SSH 先の mutt でのキー入力と文字表示、および全環境共通のテキスト選択表示を改善する。

変更は原因を確認できた箇所から段階的に行う。Windows 実機でしか判定できない描画品質とメモリは、計測可能な状態を作ってから比較する。メール本文の文字コードを gototerm が推測して変換することはしない。

## 現在確認できている事実

- `Multiplexer` がサイドバーとプレビューを1組だけ所有し、ワークベンチの表示状態もウィンドウ全体で共有している。
- タブごとに端末ペイン木は分かれているが、ワークベンチの表示／非表示は分かれていない。
- 矢印キーは端末モードに関係なく CSI 形式（`ESC [ A` など）を送っている。
- VT エンジンの `TermMode` には application cursor mode の状態が保持されているが、入力側が参照していない。
- テキスト選択の端点は押下時と解放時のスクロール量を使って再計算されるが、描画用の画面端へクランプされるため、画面外の選択が端の行に残って見える場合がある。
- 起動時に、非表示でもサイドバーとプレビューの `TerminalView` を生成している。
- `TerminalView` ごとにフォント face、グリフキャッシュテクスチャ、シェーダープログラムを所有する。
- Windows のモニター移動時はフレームバッファとビューポートを再同期するが、DPI倍率をフォントのラスタライズ寸法へ反映していない。
- Windows では設定なしの内蔵フォントを使用している。利用者の表示スケール認識は100％だが、複数モニター時に特に崩れやすい。
- 同じ Windows マシン、SSH 接続先、mutt を WezTerm または Ghostty で使う場合、矢印キーと過去メールの日本語表示は正常である。
- Windows タスクマネージャー上の観測値は WezTerm 約140MB、gototerm 約200MBである。厳密な同条件ベンチマークではないため、削減量の保証値には使わない。
- 変更前の `cargo test --all-targets` は169件成功、1件無視、失敗0件である。
- 変更前の `cargo clippy --all-targets -- -D warnings` は既存警告26件で失敗する。今回と無関係な警告は変更対象にしない。

## スコープ

### 対象

1. ワークベンチ表示／非表示のタブ単位化
2. 通常カーソルモードと application cursor mode に対応したキー送信
3. SSH 経由の UTF-8 ストリームを読み取り境界で壊さないことの保証
4. 選択範囲の絶対位置保持と、画面内に限ったハイライト描画
5. Windows のモニター移動時におけるDPI、フォント、セル、PTY、IME位置の再同期
6. Windows 内蔵フォントのヒンティング改善
7. 非表示ワークベンチの描画資源の遅延生成
8. 本文を保存しない、明示的に有効化する端末入力診断

### 対象外

- mutt のメール本文に対する ISO-2022-JP、Shift-JIS、EUC-JP 等の自動変換
- SSH サーバー、mutt、リモート側 locale の設定変更
- サイドバー幅、プレビュー高さ、フォント倍率のタブ単位化
- 描画基盤全体の一括置換
- 既存 Clippy 警告の一括修正
- 実測前のメモリ削減量の保証

## 設計

### 1. タブ単位のワークベンチ表示状態

各タブのルートと対になる軽量なタブ状態に `workbench_visible: bool` を持たせる。初期値は `false` とする。サイドバー本体、プレビュー本体、分割比率は引き続き `Multiplexer` が1組だけ所有する。

`ToggleSidebar` は現在のタブの状態だけを変更する。タブ切替時は切替先の `workbench_visible` に従ってレイアウトを再計算する。ワークベンチが閉じているタブへ移動した場合は、サイドバー、リーダー、エディターのフォーカスを解除し、端末へフォーカスを戻す。

ファイル選択やプレビュー内容の完全なタブ分離は今回行わない。今回保証する独立性は、通常表示かワークベンチ表示かの状態だけである。

### 2. 端末モードに応じたキーエンコード

特殊キーのバイト列生成を、ウィンドウイベント処理から純粋関数へ分離する。矢印キーは次のようにエンコードする。

| キー | 通常モード | application cursor mode |
|---|---|---|
| Up | `ESC [ A` | `ESC O A` |
| Down | `ESC [ B` | `ESC O B` |
| Right | `ESC [ C` | `ESC O C` |
| Left | `ESC [ D` | `ESC O D` |

`VtTerminal` は `TermMode::APP_CURSOR` の問い合わせを提供する。キーボード入力と、代替画面で矢印を代用するホイール処理は同じエンコーダーを使う。PageUp、PageDown、Functionキー、IME、既存ショートカットの送信規則は変えない。

### 3. SSH と UTF-8 ストリーム

gototerm は PTY から得たバイト列をメール本文として解釈しない。VT 制御列と UTF-8 の端末出力として処理する。

PTY の1回の読み取り、Sixel/OSC 分離後のセグメント、および UTF-8 の文字境界は一致するとは限らない。通常テキスト用のストリーム処理は、未完の UTF-8 接頭辞を次の入力まで保持し、全ての分割位置で同じ文字列へ復元できる構造にする。VTパーサー自身が分割入力を正しく保持する場合は、その性質を回帰テストで固定し、重複する独自デコーダーは追加しない。

文字化けが残った場合に備え、環境変数で明示的に有効化する診断を用意する。診断に記録してよい情報は次だけとする。

- UTF-8として不正または未完と判定されたバイト列の件数
- PTYストリーム先頭からの相対バイト位置
- その時点の application cursor、alternate screen、mouse mode

本文、入力文字列、復元可能な生バイト列、ファイル名、ホスト名は記録しない。通常時は診断処理を無効にする。

### 4. 選択範囲とスクロール

ドラッグ開始点と終了点をスクロールバック上の絶対位置として保持する。表示用の `Selection` は、その絶対範囲と現在のビューポートの交差から作る。

- 選択した文字への紐付けはスクロール後も維持する。
- 画面外へ移動した部分は描画しない。
- 一部だけ画面内にある場合は、その交差部分だけ描画する。
- 完全に画面外の場合はハイライトを描画しないが、論理上の選択は解除しない。
- コピーは表示用のクランプ済み範囲ではなく、論理上の絶対範囲を使う。
- キー入力による既存の選択解除は維持する。

### 5. Windows DPI と内蔵フォント

ウィンドウ作成時と `ScaleFactorChanged` 時に現在のスケールファクターを保持する。設定上のフォントサイズは論理ピクセルとして扱い、描画に使う物理ピクセルサイズを純粋関数で算出する。倍率1.0では既存寸法を変えない。

DPI倍率が実際に変わった場合だけ、次を同じ更新単位で再同期する。

1. FreeType の物理フォントサイズ
2. セル幅とセル高
3. グリフキャッシュ
4. 各ビューの行列数
5. PTYへ通知するセル数とセルの物理寸法
6. IME候補ウィンドウの物理位置

同じ倍率の `ScaleFactorChanged` や通常のリサイズでは、フォントとグリフキャッシュを再生成しない。

Windows の内蔵フォントには標準ヒンティングを使用し、Linux は現在の light hinting を維持する。外部フォントにも同じWindows既定を適用するが、将来設定で選べるようにするための抽象化は今回追加しない。

### 6. ワークベンチ描画資源の遅延生成

起動時は端末本体に必要な表示資源だけを生成する。サイドバーとプレビューは軽量な未生成状態とし、最初にいずれかのタブでワークベンチを開いた時点で生成する。閉じた後は破棄せず再利用し、開閉のたびに再確保しない。

ワークベンチが未生成の間、ファイル監視、プレビュー読み込み、サイドバー描画は行わない。初回表示で生成に失敗した場合はプロセス全体を終了させず、通常端末表示を維持してエラーをログへ記録する。ただし、現在の描画コンストラクターが回復不能なOpenGL初期化失敗を `panic` とする設計は、この変更だけで全面的に例外化しない。

同一フォントサイズのグリフキャッシュ共有は第2段階とする。Windows実機で遅延生成後のメモリを測り、効果が不十分な場合に別設計として扱う。

## テスト方針

各動作変更はテストを先に追加し、修正前に期待した理由で失敗することを確認する。

### タブ状態

- タブAでワークベンチを開いても、未使用のタブBは通常表示のままである。
- Aへ戻るとワークベンチ表示へ復帰する。
- タブ削除後も、残ったタブと状態の対応がずれない。
- ワークベンチ非表示のタブへ切り替えると端末へフォーカスが戻る。

### キー入力

- 通常モードと application cursor mode で上下左右の送信列が切り替わる。
- VTエンジンへ cursor mode の有効化／無効化シーケンスを与えると問い合わせ結果が変わる。
- 既存の PageUp、PageDown、IME、ショートカットの送信列が変わらない。
- 代替画面のホイール矢印代用も同じモード規則を使う。

### UTF-8

- 日本語を構成する全てのバイト位置で入力を分割しても、同じ表示結果になる。
- OSC、Sixel、通常テキストが連続し、各境界が読み取り単位をまたいでも文字を落とさない。
- 診断出力に入力本文や生バイト列が含まれない。

### 選択

- 選択範囲を維持したまま上下にスクロールできる。
- 完全に画面外の選択を画面端へ表示しない。
- 一部だけ画面内の選択は交差部分だけ表示する。
- コピー結果がスクロール前後で変わらない。

### DPI と遅延生成

- 論理フォントサイズと倍率から物理サイズを求める関数をテストする。
- 倍率1.0では既存サイズを維持する。
- 同じ倍率ではキャッシュ再生成を要求しない。
- ワークベンチを開くまでサイドバーとプレビューの描画資源を生成しない。
- 初回表示後は閉じて再度開いても同じ資源を再利用する。

## 検証

自動検証として少なくとも次を実行する。

```sh
cargo test --all-targets
cargo check --target x86_64-pc-windows-msvc
```

Windowsターゲットが環境に導入されていない場合は、導入を無断で行わず、実行できなかった理由を報告する。既存警告のため `cargo clippy --all-targets -- -D warnings` は合格条件に含めない。今回変更した箇所に新しい警告がないことは通常の `cargo clippy` 出力との差分で確認する。

Windows実機では次を確認する。

1. 設定なしの内蔵フォント、表示倍率100％で文字の輪郭を確認する。
2. 複数モニター間でウィンドウを移動し、文字サイズ、滲み、セルずれ、IME候補位置を確認する。
3. 2つのタブの片方だけでワークベンチを開き、切替時の独立性を確認する。
4. SSH先のmuttで矢印キーによるメール選択を確認する。
5. SSH先のmuttで過去送信メールを再利用し、日本語表示を確認する。
6. 起動直後、ワークベンチ初回表示後、タブ追加後のメモリをタスクマネージャーで記録する。
7. 同条件のWezTermと比較するが、単発値だけで優劣を断定しない。

## 完了条件

- 自動テストが合格する。
- ワークベンチの表示／非表示がタブごとに独立する。
- 選択範囲は文字に紐付いたまま、画面内の部分だけが描画される。
- application cursor mode の矢印キー送信が実装される。
- DPI変更時のフォント、セル、PTY、IME位置が一貫して更新される。
- 起動時に非表示ワークベンチの描画資源を生成しない。
- Windows実機でしか確認できない項目は、未確認を成功扱いせず明示して引き継ぐ。
- muttの文字化けが残る場合は診断情報から次の原因調査へ進み、根拠のない文字コード変換を追加しない。
